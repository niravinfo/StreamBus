---
title: Transport security
description: Secure connections to RabbitMQ with TLS.
---

TLS is off by default: with no `UseTls` call, both transports (the stream
protocol and the AMQP connection used for queue dead-lettering) speak plain
TCP.

## Enable TLS

```csharp
cfg.Host("rabbitmq.internal", "/", h =>
{
    h.Credentials("app", "s3cret");
    h.UseTls();
});
```

Enabling TLS switches both transports at once — there is no per-transport
toggle — and, unless you set ports explicitly, moves the defaults to the
conventional RabbitMQ TLS ports (stream `5551`, AMQP `5671`). Explicit port
calls always win, regardless of call order.

## Options

```csharp
cfg.Host("rabbitmq.internal", "/", h =>
{
    h.Credentials("app", "s3cret");
    h.UseTls(tls =>
    {
        tls.ServerName("rabbitmq.internal");
        tls.ClientCertificate("./certs/client.pfx", "pw");
        tls.AcceptableCertificateErrors(SslPolicyErrors.None);
        tls.ProtocolVersion(SslProtocols.Tls13);
    });
});
```

- `ServerName` (default: the host) — drives certificate validation (SNI
  and name matching). Set it when connecting through a load balancer whose
  certificate name differs from the host you dial.
- `ClientCertificate(path, password?)` — optional, for mutual TLS; a PFX
  file path plus optional password. The file's existence is checked at
  connect time.
- `AcceptableCertificateErrors` (default `SslPolicyErrors.None`) — policy
  errors tolerated despite failing validation; private-CA deployments
  commonly pass `SslPolicyErrors.RemoteCertificateChainErrors`. **Caution:**
  accepting `RemoteCertificateNameMismatch` or
  `RemoteCertificateNotAvailable` disables hostname verification — the TLS
  protection against man-in-the-middle attacks — and should not be used in
  production.
- `ProtocolVersion` (default: the operating system default,
  `SslProtocols.None`) — anything below TLS 1.2 is rejected.
- Calling `UseTls` again replaces the previous TLS settings (last call
  wins).

The broker side needs a listener with TLS; the integration tests do this
with a mounted certificate and configuration fragment — see
`tests/StreamBus.IntegrationTests/TlsBroker.cs` for a working reference
setup.
