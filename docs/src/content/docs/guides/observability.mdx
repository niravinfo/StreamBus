StreamBus emits standard .NET observability signals: an aggregated health
check, `System.Diagnostics.Metrics` instruments, activity spans, and log
events. Wire them to OpenTelemetry or the host's dashboard — no extra
packages required.

## Health

The `streambus` health check reports both connection and registration
state as data entries:

- `{vhost}|{busType}` — the live connection state for that bus (for
  example `/|StreamBus.DefaultBus`).
- `{vhost}|{registration}` — one row per consumer or declaration. Consumer
  rows carry the bus type so several buses on one vhost stay attributable:
  `endpoint:{busType}:{stream}` for typed receive endpoints, and
  `raw:{busType}:{stream}` for `IStreamBus.ConsumeAsync` (with `:2`, `:3`,
  ... on repeat consumes). Declarations use `declare:{name}`. The value is
  `consumer:<state>` or `declare:<state>`, with the failure reason and
  `since` timestamp appended when present.

```csharp
var report = await health.CheckHealthAsync(ct);
var entry = report.Entries["streambus"];
var connection = entry.Data["/|StreamBus.DefaultBus"];
```

The connection monitor runs at `h.MonitorInterval(...)` (default 5
seconds), so a broker that disappears is detected on that cadence.

## Metrics

Meter name: `StreamBus`.

| Instrument | Kind | Tags |
|---|---|---|
| `streambus_partition_backlog` | up-down counter | vhost, bus, stream, partition, reference |
| `streambus_partition_inflight` | up-down counter | vhost, bus, stream, partition, reference |
| `streambus_partition_retry_blocked` | up-down counter | vhost, bus, stream, partition, reference, failure_mode |
| `streambus_connection_state` | up-down counter (int) | vhost, bus |
| `streambus_offset_store_rejected_total` | counter | vhost, bus, stream, partition, reference |
| `streambus_offset_regressed_total` | counter | vhost, bus, stream, partition, reference |
| `streambus_offset_fallback_total` | counter | vhost, bus, stream, partition, reference |
| `streambus_pipeline_duration` | histogram (seconds) | kind = publish \| consume |

The backlog gauge measures the consumer-held unprocessed backlog (last
delivered offset minus last stored offset per partition), not
broker-total lag — a growing stream nobody consumes reports 0.

## Activities

`ActivitySource` name: `StreamBus`. It costs nothing when no listener
samples it.

| Span | Kind | Tags |
|---|---|---|
| `streambus.publish` | Producer | `streambus.stream`, `streambus.size`, `streambus.routing_key` (super only) |
| `streambus.consume` | Consumer | `streambus.stream`, `streambus.partition`, `streambus.offset` |

Consume spans add an `exception` event when a delivery fails, and carry an
`ActivityLink` when the AMQP `correlation-id` holds a valid W3C
`traceparent` (ids produced by StreamBus are Guids, so the link applies to
foreign producers only).

## Logs

Expect warnings — not errors — for routine redelivery: handler failures
during retry, exhausted budgets naming stream, partition, offset, and
attempts, error-destination hand-off retries, and `OnExhausted` faults
noting the attach recycle. Shutdown races log at debug.
