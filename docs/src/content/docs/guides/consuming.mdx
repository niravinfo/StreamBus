Endpoints consume from streams through `ReceiveEndpoint`. The consumer
group is required and verbatim. On a super stream, one group distributes partitions across instances; different groups consume independently.

## Register an endpoint

```csharp
builder.Services.AddStreamBus((_, cfg) =>
{
    cfg.ReceiveEndpoint("orders", e =>
    {
        e.Consumer<OrderConsumer>("billing");
    });
});
```

## Scale out

Super streams distribute partitions, not individual messages. With one group,
instances take ownership of different partitions (`SingleActiveConsumer`
applies per partition), so adding instances reads more partitions in parallel.

Plain streams are different: with the default `SingleActiveConsumer = true`,
one instance owns the group's cursor and the others stand by for failover.
They do not add throughput. Use a super stream when you need horizontal scale.

A second endpoint with a different group reads the stream from its own offset.
Delivery is at-least-once, so consumers must tolerate duplicates.

## Independent consumers

A second endpoint with a *different* group reads the same stream from
its own offset, so billing and shipping each see every message:

```csharp
cfg.ReceiveEndpoint("orders", e =>
{
    e.Consumer<OrderConsumer>("billing");
});

cfg.ReceiveEndpoint("orders", e =>
{
    e.Consumer<OrderConsumer>("shipping");
});
```

## Offsets

Consumers track their position in the stream. Streams are append-only
and retain messages per the stream's retention policy, so a group can
replay from any offset when it needs to.
