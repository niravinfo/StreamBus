## Retry

Global retry is strict and unbounded by default. Endpoints can override the
schedule:

```csharp
builder.Services.AddStreamBus((_, cfg) =>
{
    cfg.UseRetry(r => r.Intervals(TimeSpan.FromSeconds(1), TimeSpan.FromSeconds(5)));

    cfg.ReceiveEndpoint("orders", e =>
    {
        e.Consumer<OrderConsumer>("billing");
        e.UseRetry(r => r.Immediate(3));
    });
});
```

## Exhaustion

When retries run out, a message goes to a configured destination, an owning
callback, or — when neither is set, and the schedule is bounded — the
per-stream classic `{stream}_error` queue:

```csharp
cfg.ReceiveEndpoint("orders", e =>
{
    e.Consumer<OrderConsumer>("billing");
    e.UseRetry(r => r.Immediate(3)); // bounded
    // No destination or callback: exhausted messages land in orders_error.
});
```

## Escaping the error queue

The `orders_error` queue is a regular classic queue: requeue moves
messages back for another attempt, and dead-letter continues the escape
hatch chain when configured.
