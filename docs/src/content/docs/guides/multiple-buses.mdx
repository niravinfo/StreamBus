---
title: Multiple buses
description: Run independent buses with marker types.
---

One `AddStreamBus` registers the default bus (`IStreamBus`); each
`AddStreamBus<TBus>` registers one more (`IStreamBus<TBus>`), identified by
a marker type. The non-generic overload may be used at most once per
service, and each marker at most once. Registrations sharing a vhost must
agree on the connection identity.

A marker type is any class you own:

```csharp
public sealed class OrdersBus;
public sealed class BillingBus;
```

## Two buses, one application

```csharp
services.AddStreamBus<OrdersBus>((_, cfg) =>
{
    cfg.Host("localhost", "/orders", h => h.Credentials("app", "s3cret"));
    cfg.Publish<OrderEvent>("orders");
    cfg.ReceiveEndpoint("orders", e => e.Consumer<OrderConsumer>("orders-team"));
});

services.AddStreamBus<BillingBus>((_, cfg) =>
{
    cfg.Host("localhost", "/billing", h => h.Credentials("app", "s3cret"));
    cfg.Publish<OrderEvent>("invoices");
    cfg.ReceiveEndpoint("invoices", e => e.Consumer<SharedConsumer>("billing-team"));
});
```

Publish registrations are per bus: the same message type on two streams of
one bus is an ambiguity error, while the same type on two buses resolves
independently through each bus's own route table.

Inject a specific bus with its marker:

```csharp
public sealed class CheckoutWorker(
    IStreamBus<OrdersBus> orders) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        await orders.PublishAsync(new OrderEvent("o-1"), ct);
    }
}
```

## Shared consumer classes

A consumer class shared by two services (or two buses) must be registered
with a different group per bus — there is no default to collide on:

```csharp
cfg.ReceiveEndpoint("orders", e => e.Consumer<SharedConsumer>("orders-team"));
cfg.ReceiveEndpoint("invoices", e => e.Consumer<SharedConsumer>("billing-team"));
```

Each bus keeps its own cursor, so the two groups consume independently.
