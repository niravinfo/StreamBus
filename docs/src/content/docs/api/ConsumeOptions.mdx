title: ConsumeOptions
---

Raw consume settings: apply whether the stream is a super stream, the consumer-group identity, the start offset, retry/error-handoff behavior, and the attach readiness policy.

```csharp
public class ConsumeOptions
```

## Properties

### ConsumerGroup

Consumer-group consumerGroup; the group is the cursor identity and is used verbatim. Required: a missing group throws StreamBusConfigurationException at attach instead of guessing; over the broker's 255-byte limit is also an error.

```csharp
ConsumerGroup
```

### ErrorPublishTimeout

Timeout for the confirmed publish to the error stream; null waits indefinitely (the partition loop's cancellation token is the only bound). A lost confirmation surfaces as transient so the partition dispatch gate is never wedged; the hand-off is retried without advancing.

```csharp
ErrorPublishTimeout
```

### ErrorStream

Error-stream destination for exhausted messages (an alternative to ConsumeOptions.OnExhausted, which it is mutually exclusive with). The stream is declared from the destination's stream spec; consuming or draining it afterwards is the application's responsibility.

```csharp
ErrorStream
```

### IsSuperStream

true when the stream is a super stream (all partitions are consumed).

IsSuperStream

### OnExhausted

Terminal handler for exhausted messages. The callback owns the outcome: it replaces any hand-off destination (on the raw ConsumeOptions path ConsumeOptions.ErrorStream and ConsumeOptions.OnExhausted are mutually exclusive). Returning advances past the message; throwing recycles the attach (redeliver, never skip). Resolve services from ExhaustedContext.Services; the endpoint configurator exposes the same callback as OnExhausted.

```csharp
OnExhausted
```

### Readiness

Gates the consumer attach: fail fast, wait bounded, or wait indefinitely (default fail fast).

```csharp
Readiness
```

### Retry

Retry policy. The default sets no attempt limit: a failing handler is retried forever and its partition waits, so nothing is skipped. To cap attempts and hand the message off instead, set RetryPolicy.MaxAttempts and configure an error destination: ConsumeOptions.ErrorStream (an error stream) or ConsumeOptions.OnExhausted (a callback). The endpoint API also offers a dead-letter queue (DeadLetterToQueue).

```csharp
Retry
```

### SingleActiveConsumer

Single-active-consumer per (stream, consumerGroup): only one instance in the group receives deliveries. Set false to fan out to every instance (never run two offset writers on one consumerGroup outside SAC).

```csharp
SingleActiveConsumer
```

### StartOffset

Start-offset policy for the group; defaults to resume-or-first.

```csharp
StartOffset
```
