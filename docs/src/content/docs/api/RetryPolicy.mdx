Retry timing and attempt limit. RetryPolicy.MaxAttempts is the total number of attempts per message, including the first; null means no attempt limit (retried forever), 1 means no retry.

```csharp
public class RetryPolicy
```

## Properties

### BaseDelay

Base delay for the exponential schedule; growth is fixed at ×2 per attempt.

```csharp
BaseDelay
```

### DelayCalculator

Optional caller-supplied delay. When set, it overrides the exponential schedule; throwing or negative results fall back safely.

```csharp
DelayCalculator
```

### MaxAttempts

Total attempts including the initial one. null means no attempt limit (retried until it succeeds); 1 means no retry.

```csharp
MaxAttempts
```

With no attempt limit there is no hand-off destination: a handler that keeps failing blocks its partition until it succeeds (back-pressure; nothing is skipped or dead-lettered). To cap attempts and hand the message off, set RetryPolicy.MaxAttempts and configure an error stream, a dead-letter queue, or an OnExhausted callback.
