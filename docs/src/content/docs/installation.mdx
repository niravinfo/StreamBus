## Prerequisites

| Requirement | Notes |
|---|---|
| .NET 10 SDK | StreamBus targets `net10.0`. |
| RabbitMQ 4.x | With the stream plugin enabled (below). |
| A non-`guest` user for remote brokers | RabbitMQ refuses `guest` from non-localhost connections. |

## Enable the stream plugins

RabbitMQ Streams is served by a plugin; a stock broker does not listen
on the stream port until it is enabled. Enable both plugins:

- **`rabbitmq_stream`** — the stream protocol itself; listens on port
  `5552` by default.
- **`rabbitmq_stream_management`** — the `api/stream/*` endpoints in
  the management UI, for inspecting and killing stream connections.

<Tabs>
  <TabItem label="Linux">
    ```bash
    rabbitmq-plugins enable rabbitmq_stream rabbitmq_stream_management
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    rabbitmq-plugins.bat enable rabbitmq_stream rabbitmq_stream_management
    ```
  </TabItem>
</Tabs>

Plugin enablement is asynchronous: the stream listener accepts
connections a few seconds after the command returns, and the broker
log (`rabbit@host.log`) shows the plugins starting. If the client
can't connect on `5552`, that log is the first place to look.

The stream listener can be reconfigured in `rabbitmq.conf`
(`stream.listeners.tcp.default`, advertised host/port); StreamBus
connects to whatever the broker advertises.

## Install the package

```xml
<PackageReference Include="StreamBus" Version="0.4.0-beta.1" />
```

StreamBus depends on the extension packages you already use
(`Microsoft.Extensions.Hosting`, `Microsoft.Extensions.Diagnostics.HealthChecks`)
and the official `RabbitMQ.Stream.Client` for the wire protocol — you
add one package.
